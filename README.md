# 采集调度策略管理工具

离线版采集调度策略配置工具，涵盖站点登记、模板编排、代理轮换、限速调节、反爬策略、增量水位与结果校验规则，所有配置持久化到浏览器本地存储。

这是一个**纯前端**管理平台：React + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 React + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/views/site/RevisionWorkbench.tsx   站点修订与变更传播工作台
│   ├── src/views/impact/     受影响采集站点配置清单（复验范围）
│   ├── src/api/local-service.ts    本地数据服务：列表、筛选、动作流转、导出
│   ├── src/api/impact-service.ts   影响传播服务：修订落库、中断恢复、复验、清单导出
│   ├── src/data/impact-engine.ts   影响范围计算：字段判定、两种口径、复验核对
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `scraper-strategy-studio:entries` 这一项，或调用 `resetModule(模块)`
  （重置站点登记会一并清空影响清单，因为清单快照引用的站点已经不在了）。

## 站点修订与变更传播

站点登记页下方是「站点修订与变更传播」工作台，只对**已激活**站点发起修订：

1. 改字段（含限速规则的每秒请求上限）后，右侧按变更字段逐项列出命中模板、命中作业与判定原因。
2. 同时给出两种落库路线的复验范围与清单行数：
   - 按每个变更字段合并影响范围（字段并集，复核依据固定用这一口径）；
   - 按最后确认的整条站点记录确定范围。
   两条路线结果不同时会明确提示，选定哪条，任务编排版本就随之确定。
3. 点「生成完整影响清单并落库」：站点字段、影响清单、任务编排待处理清单在**一次写盘**里同时生效。
   保存失败时上一份可执行清单保持原样，作业不会读到只算了一半的集合。
4. 「暂存修订现场（模拟中断）」只写草稿，先记下字段并集范围与当前业务证据；恢复后不会跳回先前版本。
5. 顶部的「保存失败演练」可以复现写盘失败路径，不触碰真实数据。

`/impact` 页是值班员的复验视图：按站点编号查当前/历史复验范围、看规则标准与逐项核对结果、
导出清单数据（CSV）和复核记录（JSON）。`/spider` 页读取清单后只把清单里的作业标记为待复验，
其余作业继续按原站点版本执行。
